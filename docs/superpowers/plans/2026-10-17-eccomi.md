# Eccomi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web app mobile-first per segnare le presenze giornaliere dei volontari di Dare, con anagrafica, riepilogo per periodo ed export PDF, distribuita con Docker.

**Architecture:** Un'unica app Next.js (App Router, server components + server actions) che parla direttamente con PostgreSQL tramite il driver `postgres`, in SQL semplice. La logica pura (date, sessione, import, riepilogo, tabella PDF) sta in `lib/` ed è testata con Vitest. Le operazioni sul DB hanno test di integrazione su un database `eccomi_test`. In locale tutto gira nativo (Postgres installato con Homebrew, `npm run dev`); Docker si usa **solo in produzione**, con `docker-compose.yml` e due servizi: `app` e `db`.

**Tech Stack:** Next.js (ultima stabile, `create-next-app@latest`, TypeScript, Tailwind, App Router, cartella `src/`), React, Tailwind CSS, `postgres` (porsager), Vitest, `jspdf` + `jspdf-autotable`, Docker, PostgreSQL 17.

**Spec:** `docs/superpowers/specs/2026-10-17-eccomi-design.md`

## Global Constraints

- UI interamente in **italiano**.
- Colore principale **blu**; grafica minimale. Ogni task con UI usa le skill `frontend-design` e `design-taste-frontend` (quest'ultima solo per le regole di stile, non per il flusso da landing page).
- Mobile-first: target principale è il telefono (larghezza 375px), senza scroll orizzontale della pagina (la griglia del riepilogo scorre dentro il proprio contenitore).
- Ordinamento volontari ovunque: per **nome**, poi cognome, con `Intl.Collator('it', { sensitivity: 'base' })`.
- "Oggi" = data nel fuso **Europe/Zurich**, formato `YYYY-MM-DD`.
- Le date viaggiano ovunque come stringhe `YYYY-MM-DD`, mai come `Date` (il driver va configurato per non convertire il tipo `date`, vedi Task 1).
- Accesso: una sola password da `APP_PASSWORD`; cookie `eccomi_session` httpOnly, sameSite `lax`, durata **90 giorni**, `secure` solo con `NODE_ENV=production`.
- Variabili d'ambiente: `DATABASE_URL`, `APP_PASSWORD`, `SESSION_SECRET`, `APP_PORT` (default 3000), `POSTGRES_PASSWORD`.
- **Locale senza Docker:** PostgreSQL 17 da Homebrew (`brew install postgresql@17`, `brew services start postgresql@17`), con i database `eccomi` e `eccomi_test`.
- In produzione Postgres **non** pubblica porte: lo raggiunge solo il container `app`, sulla rete interna del compose.
- Produzione: `https://eccomi.hsdscp.duckdns.org`, dietro un reverse proxy già esistente che gestisce HTTPS.
- Nessuna cancellazione dei volontari, solo disattivazione.
- Nessuna nuova dipendenza oltre a quelle elencate nel Tech Stack.

## Review Focus

1. **Responsabile che segna dopo le 22/23 (ora svizzera) o subito dopo mezzanotte:** la presenza finisce sul giorno di Zurigo, non su quello UTC. → test in Task 2 (`todayZurich`).
2. **Doppio tocco rapido, o due telefoni che segnano la stessa persona:** mai doppioni né errori a schermo; lo stato finale è coerente. → test in Task 4.
3. **Elenco incollato "sporco"** (righe vuote, spazi doppi, una sola parola, stessa persona ripetuta o con maiuscole diverse, `\r\n` da Excel): nessun crash, niente doppioni, conteggio importati/saltati corretto. → test in Task 3.
4. **URL del riepilogo manomesso o incoerente** (`from` > `to`, date non valide, parametri mancanti): si torna a "oggi" senza errore 500. → test in Task 5.
5. **Volontario disattivato che ha presenze nel periodo** (anche se disattivato oggi stesso): compare nel riepilogo e nel PDF, ma non nella lista presenze. → test in Task 5 e Task 4.
